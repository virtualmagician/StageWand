StageWand OSC Requests

StageWand — the ESP32-C6 AMOLED hardware cue controller (repo) — already drives StageWizard through the dev-branch OSC hooks with no host changes. This document lists the outbound OSC feedback that would make the wand a first-class surface: what to send, when, and why, in priority order. The wand's client side for every P1 item is already implemented and waiting.

Baseline

What dev already has (and StageWand already uses)

Read from OSCServer.swift and WebRemoteServer.swift on dev.

SurfaceDirectionDetails
OSC / UDP :53100in → host/stagewizard/go · /stopall · /next · /prev · /toggle · /panic · /stagewizard/cue/<number>/fire. OSC 1.0, tags i f s parsed, bundles supported, address-only dispatch.
HTTP :53200out ← hostGET /status → {standingByNumber, standingByName, notes, runningCount, showMode, panicking} — StageWand v1 polls this at 2 Hz as its interim feedback path.

The ask

Missing pieces, in priority order

P1  OSC status feedback — replaces HTTP polling

Everything GET /status already knows, pushed as OSC so a microcontroller doesn't need an HTTP client and gets sub-100 ms updates. Send on change plus a full refresh on subscribe.

AddressArgsWhenNotes
/stagewand/ping(none)wand → host, every 1 sImplicit subscription + keepalive. Host records the datagram's source IP:port as a feedback target; drop targets silent for >5 s. Unknown addresses are already ignored silently, so wands can ship this today.
/stagewizard/status/standingbys number, s nameon change + on subscribeEmpty strings when nothing is standing by. This is the wand's home screen.
/stagewizard/status/runningi counton change + on subscribeThe web remote's runningCount.
/stagewizard/status/panici 0|1on change + on subscribeWand shows a hard red state; must never be stale.
/stagewizard/status/showmodei 0|1on change + on subscribeWand can lock its own editing surfaces in show mode.
Implementation note. Reply-to-sender needs no new socket or config: answer to the source address of any received datagram (NWConnection per-flow, as the listener already tracks). An OSC encoder is the only new code — the mirror of parseMessage, ~30 lines. StageWand's client side already listens on its send socket and ingests all five addresses; the moment the host transmits, wands go live with zero client changes.

P2  Cue context — what the wand shows around the playhead

AddressArgsWhenNotes
/stagewizard/status/windowi index, i total, s prevNum, s prevName, s nextNum, s nextNameon change + on subscribeA 3-cue window around the playhead beats a full cue-list dump: fits a 1.8″ screen, O(1) traffic, no sync protocol. (A full-list dump can come later if ever needed.)
/stagewizard/status/notess noteson change + on subscribeAlready in /status; operators want the standing-by cue's notes on the wand.
/stagewizard/status/elapsedf seconds, f duration2 Hz while anything runsDrives a progress bar. duration ≤ 0 = indefinite (camera/loop).
/stagewizard/cue/<number>/select(none)wand → hostCommand-side gap: move the playhead / stand a cue by without firing. The wand's cue-list taps should arm, not fire.

P3  Faders & discovery — needs a product decision first

ItemSketchOpen question
/stagewizard/level/<target>f 0.0–1.0The wand has 4 hardware submasters. What do they map to in StageWizard's model — master out, render layers, output groups, or tagged cue groups? Define the target vocabulary; the wand adapts.
Bonjour advertisement_stagewizard._udp on :53100Lets wands find the host with zero configuration — a big deal for hardware with no keyboard. NetService/NWListener advertising is a few lines.

Contract

Ground rules both sides keep

Plain OSC 1.0 messages, type tags limited to i f s (exactly what the dev-branch parser accepts today — the wand's parser mirrors it). No bundles required for feedback; each state item is its own message so a lost datagram only stales one field until the next change or subscribe-refresh. All feedback goes to every live subscriber; a subscriber is any source address heard from in the last 5 seconds. StageWand keeps HTTP /status polling as an automatic fallback whenever OSC feedback is absent, so the two can ship in either order.
